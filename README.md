# 国际会议同声传译和发言队列控制

源提示词摘要：主持人维护代表发言队列、剩余时间、议题和临时插话；翻译团队维护多语种频道、术语和译员交接；字幕人员修正实时文本。队列调整保留版本，发言者切换后旧译文不会误绑定，并提供低延迟大屏模式和多会议厅隔离。

## 技术栈

Qwik City、TypeScript、Qwik UI、Qwik stores、TanStack Query、Modular Forms、Zod、qwik-speak。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62029`

> 环境运行时为 Node 20，而 qwik-city 依赖的 undici 8 需要 Node 22+ 的 `worker_threads.markAsUncloneable`。`node-polyfill.cjs` 在启动前补一个空实现（Node 22+ 上自动跳过），已通过 `NODE_OPTIONS=--require ./node-polyfill.cjs` 注入到 dev/build/preview 脚本。升级到 Node 22+ 后可移除该 polyfill 与脚本里的 `NODE_OPTIONS`。

## 接力链同传（源语言 → 中间语言 → 目标语言）

小语种发言找不到直译时，调度员让英语先接一段，再转给目标语种。发言、频道、译员被接成一条接力链：

- 每条发言写清源语言、中间语言、目标语言；接力链按「发言 × 目标语种」建立，复用频道与译员。
- 分段携带三个版本号（原文 / 中间译文 / 字幕），字幕是否有效由版本是否一致推导。
- **中间段没确认前下游不出字幕**：接力译员提交中间译文后需「确认中间段 · 建立断点」，目标语种才能发布字幕；大屏只播当前版本的已发布字幕。
- **发言一变，下游字幕立即失效重算**：发言切换时旧发言的接力链归档、大屏字幕立刻撤下；在链内「修正原文」会让原文版本 +1，旧字幕立即失效并重算。
- **接力失败后从断点恢复**：中间译员换人（频道「完成交接」）或频道掉线（「模拟掉线」）会触发恢复——已确认分段保留（中间译文冻结、字幕保留），只把未确认分段清空从原文重译，不重放整条链；全部重新确认后链恢复 active。

## 可用流程

- 多会议厅独立维护代表、议题和发言队列，切换厅时数据互不影响。
- 发言人从排队、发言中、完成到跳过，支持临时插话和剩余时间调整。
- 多语种频道维护译员、术语和交接；交接后新增字幕归属新译员。
- 实时字幕支持版本化修正，低延迟模式只保留关键状态并停用非必要动态。
- 数据保存在浏览器 localStorage，刷新后继续保留。
